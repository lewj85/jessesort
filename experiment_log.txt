1.1 BENCHMARK AND AUDIT STANDARD
- E077 is the current whole-sort benchmark methodology; E100 centralizes its seed policy.
- Canonical `make run` / `make run500` / `make bench500` profile:
    * C++20, -O3, -march=native, -DNDEBUG
    * n = {1k, 10k, 100k, 1m}
    * 2 untimed warmups per workload
    * 500 measured paired trials at 1k/10k/100k
    * 50 measured paired trials at 1m for the all-size sweep
    * one deterministic unique input seed per randomized trial
- MANDATORY POST-CHANGE ACCEPTANCE RULE: after every algorithmic/performance code change, run the
  full canonical benchmark above across ALL SEVEN variations (V1-V7), even when the code change
  directly targets only one variation. Use the benchmark's normal persisted-results resume handling
  after shell/tool timeouts; resume the SAME run directory until the sweep is complete.
- Every performance-change evaluation must display/preserve all seven generated ratio tables. Narrow
  A/B or phase-local harnesses are diagnostic only and do not replace this full-suite acceptance run.
- PERMANENT FULL-SUITE REGRESSION AUDIT: acceptance is not complete until every canonical timing cell
  (all 12 workloads x V1-V7 at every tested size) is compared against the immediately previous accepted
  authoritative baseline using old median us, new median us, and new/old ratio. ANY apparent regression
  greater than 1.0% at ANY size or input must be investigated before retention is finalized. Do not waive
  this because a workload is noisy, very fast, or supposedly unaffected by the change: repeat the flagged
  cell under matched canonical conditions (normally 500 trials; preserve the canonical 1m policy for the
  full sweep, and use a targeted confirmation cohort when needed) and determine whether the regression is
  reproducible. A retained optimization must not silently give back prior >=1% wins elsewhere. Random must
  always receive explicit regression review even when it is below the threshold.
- When a complete canonical resumed sweep conflicts with a smaller ad-hoc/end-to-end timing sample,
  treat the canonical sweep as authoritative for repository-level retention decisions. Use the narrow
  harness only to explain mechanism, not to overrule the canonical result by itself.
- Targeted numeric-size invocations use the requested trial count directly; they do not
  automatically apply the 1m 10:1 reduction.
- Every algorithm and std::sort receive the exact same source vector within a trial.
  Execution order rotates by trial and reverses every eight-trial block. Correctness
  validation is outside timed regions.
- Canonical seed policy for normal benchmarks and one-off A/B tests:
    * base seed: `jessesort::bench::kCanonicalBaseSeed` (0x8A5CD789)
    * mixer: `jessesort::bench::trial_seed()` in `benchmarks/benchmark_seed.h`
    * do not invent a new seed population for an ordinary one-off test; explicitly label
      intentional held-out/confirmation cohorts instead.
- Preserve raw paired timings. Report robust statistics such as median, p25/p75, IQR,
  MAD, ratio of medians, and median paired ratio as appropriate; do not silently trim
  outliers.
- For header-only/template-heavy close A/B tests, prefer a same-binary or phase-isolated
  causal harness. E099 showed structured workloads can exhibit large first/second-sort
  allocator/process-state effects; fork-isolated paired children are appropriate when
  ordinary same-process alternation remains biased.
- Canonical workload families (frozen in E180C): Random, Sorted, Reverse, Sorted+Noise(5%),
  Sorted+Noise(10%), Random%25, Alternating, Sawtooth, MixedDirectionRuns, BlockSorted, OrganPipe,
  and Rotated. Retain/reject decisions use these exact generators; synthetic diagnostics may explain
  mechanisms but may not tune production policy unless first promoted to the canonical suite.
- CURRENT PERFORMANCE SNAPSHOT: E189 canonical acceptance is the latest completed public V1-V7 timing set.
  Full 1k/10k/100k/1m tables are mirrored in `benchmarks/baselines/e189_current_benchmark.md`; E180C
  remains the frozen historical pre-E181 baseline rather than the current-code timing snapshot.
- Structured-generator scaling (E180C): use one consistent target scale ~= n^(2/3) everywhere
  E180B introduced sqrt(n). Sawtooth uses that target as its regular period; BlockSorted uses seeded
  variable ascending block lengths around it before block-order shuffling; MixedDirectionRuns uses seeded
  variable monotone run lengths around it with randomized direction/range/step. This keeps both run count
  and run length growing with n without the overly short-run sqrt(n) regime discovered in E180B.
- `Rotated` intentionally keeps a randomized split. E100 audited 500 canonical 100k
  trials: mean split/discontinuity position 49.322%, median 49.954%, decile counts close
  to uniform, and exactly 250/500 positions before versus at/after the nominal 50%
  freeze decision point. Keep the randomized generator; control it through canonical
  seeds rather than deterministic stratification.
- Benchmark runs are resumable with `./benchmark <trials> <size|all> <warmups>
  <existing_run_dir>` and reconstruct summaries only from complete paired trials.
- Validate workload generators rather than trusting labels. Test non-integer types and
  custom comparators separately when genericity/correctness/performance conclusions
  depend on value representation.
- Do not assume an optimization transfers between variations; propagation gets its own
  causal evidence unless the change is purely mechanical/documentary.

V1. ACTUAL PHYSICAL PILES
- Header: `include/jessesort/v1_actual_piles.h`
- Namespace: `jessesort::actual_piles`
- Representation: vector-backed physical patience piles with separate tail mirrors.
- Early routing: equality preserves the current game. A >=32-element monotone prefix is
  materialized directly. Otherwise the true first-64 probe routes Random-like inputs to
  direct bit-walk tail search, high-locality inputs to exact previous-pile hint + binary
  fallback, and ambiguous inputs to ordinary binary search (E046/E047/E056).
- E099 natural-run route: after an initial monotone prefix covering >=12.5% of n, later
  strict runs of length >=8 whose endpoints resolve to one physical pile are appended in
  bulk. This is retained and especially effective for OrganPipe/Rotated.
- E109 convergence baseline: V1 now uses the same non-freezing Random merge predicate as V2/V3:
  the first-64 `earlyRandomLike` signal + common 3.5/4.25/5.0 pile-density thresholds + the
  <=96-byte trivially-copyable type gate. The older V1-only minority-game balance predicate is
  no longer part of the common starting policy.
- Merge kernel: E083 raw pointers + E085 bidirectional low/high-end branchless merge are retained.
- E111 removed selective PowerSort from the common V1/V2/V3 policy after cross-variation revalidation.
- E115 consolidates V1/V2/V3 onto one shared ends-based adjacent-pair post-flatten merge driver with
  adaptive ordered-boundary probing and the retained E045/E085 routing/kernel choices.

V2. SIMULATED BLUEPRINT
- Header: `include/jessesort/v2_simulated.h`
- Namespace: `jessesort::simulated`
- Representation: sentinel-free value tails plus packed 32-bit blueprint tags.
- Early insertion routing: >=32 monotone-prefix recognition; first-64 structure signal;
  one-time no-hint continuation for sustained Random-like structure; split exact-hint
  path for >=75% hint locality; ordinary search otherwise (E043/E065).
- E098 natural-run route: if the initial strict monotone prefix covers >=12.5% of n,
  later strict runs of length >=8 are endpoint-tested and blueprint-tagged in bulk when
  both endpoints map to the same pile. Exact blueprint/count/tail equality was required
  in A/B validation.
- Reconstruction: descending-game runs first, ascending-game runs second. E081 normalizes
  packed local tags to global run IDs before scatter. E086 keeps an explicit `step[]`
  table below 500k and derives direction from normalized run ID at >=500k, where the
  metadata-stream reduction wins.
- E109 convergence baseline replaces V2's old pre-E085 E053 density coefficients with the shared
  non-freezing 3.5/4.25/5.0 thresholds. V2 keeps its `earlyRandomLike` prerequisite, E045 gallop
  selector, and adaptive ordered-boundary probing. E101 previously removed the obsolete E063 per-pair
  imbalance fallback. E111 removed selective PowerSort; E115 moves V2 onto the same shared ends-based
  adjacent-pair post-flatten merge driver used by V1/V3.
- High-entropy merge: E082 raw pointers + E085 bidirectional branchless merging retained.
  E092 widened the merge-only trivially-copyable type cutoff through 96 bytes; 128 bytes
  crossed to neutral/slower. Do not infer the same cutoff for insertion copies.

V3. SIMULATED BLUEPRINT + IN-PLACE PERMUTATION FLATTENING (NO FREEZE)
- Header: `include/jessesort/v3_inplace_simulated.h`
- Namespace: `jessesort::simulated_inplace_flatten`
- This is a NON-FREEZING controlled variation of V2. E156 audited/reconciled the pair:
  V3 now shares V2's pre-Patience router, simulated insertion engine, random-merge selector,
  and post-flatten merge driver. Its intentional distinguishing mechanism is in-place
  permutation flattening instead of V2's streaming reconstruction. No large-N flatten cutoff
  is retained; poor V3 flatten scaling is allowed to remain visible as experimental evidence.
- This is a NON-FREEZING variation. Insertion shares V2 semantics, including E065 routing
  and retained E099 natural-run batching. Flattening converts blueprint tags to destinations
  and permutes the array in place with cycle swaps.
- E109 convergence baseline aligns V3 with V1/V2 on descending-game-first materialization and
  common 3.5/4.25/5.0 density thresholds. V3 still differs architecturally by performing the
  blueprint flattening as an in-place cycle permutation. E111 removes selective PowerSort; E115
  moves V3 onto the same shared ends-based adjacent-pair post-flatten merge driver as V1/V2 while
  retaining adaptive ordered-boundary probing, E045 gallop policy, E085 kernel, and <=96-byte type gate.
- E104 revisited E045 under the current E085/E093/E102 cost model with high trial counts.
  V3 now retains the same final-layout 5/7 gallop-trigger selector used by V2: trigger 5
  only for non-branchless, non-PowerSort layouts with 12-128 runs and largest run <=1.25x
  the mean; trigger 7 remains the default.
- Retained as an experimental reconstruction/memory comparison, not the default V2 path.

V4. EARLY FREEZE + ONE LARGE DEFERRED OVERFLOW RUN
- Header: `include/jessesort/v4_single_overflow.h`
- Namespace: `jessesort::simulated_early_freeze_single_overflow`
- E049 one-time first-64 hinted/no-hint routing remains outside the long insertion loop.
- Freeze policy: 50% is the decision point. V4 may extend ordinary pile creation to a
  strict next power-of-two cap only under its conservative selected policy; therefore
  50% is not always the exact physical freeze boundary.
- E099 natural-run batching is retained in a freeze-aware form that preserves the freeze
  transition and keeps the power-of-two extension interval scalar.
- Overflow: one contiguous deferred region sorted once with std::sort.
- Merge routing retains the post-insertion Random signal, E085 bidirectional branchless
  kernel, and E093 <=96-byte trivially-copyable merge cutoff. Selected PowerSort-style
  scheduling remains limited to its retained run-structure conditions.

V5. EARLY FREEZE + DEFERRED-SORT 32-ELEMENT OVERFLOW BANDS
- Header: `include/jessesort/v5_deferred_bands.h`
- Namespace: `jessesort::simulated_early_freeze`
- E049 one-time first-64 hinted/no-hint routing; 50% nominal freeze decision point with
  the retained broad selected power-of-two extension policy.
- E099 natural-run batching is retained with the STRONGER V5/V6 gate: after the >=12.5%
  initial monotone prefix, the first continuation run must itself be >=8 before the route
  is enabled. This preserves OrganPipe gains while avoiding the broad-gate Rotated loss.
- Overflow: deferred 32-element bands. E090 uses a fixed specialized network for exact
  full 32-element bands; partial/conservative cases retain std::sort. The network was
  ~28.4% faster locally over 4,096,000 int-band sorts, with diluted whole-sort impact.
- Merge routing retains E085 bidirectional branchless merging and E093 <=96-byte
  trivially-copyable cutoff. V5 keeps its variation-specific dominant-endpoint merge
  deferral; global PowerSort and simple adaptive band shaping were rejected.

V6. EARLY FREEZE + LIVE-SORTED 32-ELEMENT OVERFLOW BANDS
- Header: `include/jessesort/v6_live_bands.h`
- Namespace: `jessesort::simulated_early_freeze_live`
- Shares V5's early-freeze base structure and nominal 50%/selected power-of-two extension.
- Uses the same stricter E099 first-continuation-run >=8 natural-run gate as V5.
- E179 adds the retained STRICT post-insertion overflow router. Weak/fragmented structure keeps
  live-sorted 32-element bands; clearly ascending low-pile structure uses E175 ascending natural
  runs; clearly descending low-pile structure and high-pile long monotone structure use E176
  bidirectional natural runs with 32 as a minimum weak-structure granularity, not a cap.
- The router combines overflow fraction, final frozen pile density, and the first 32 overflow value
  transitions collected inline. Sampling is suppressed when freeze-time pile geometry already makes
  both natural tiers impossible (piles>64 and density>0.006).
- Merge routing retains E085 bidirectional branchless merging and E093 <=96-byte cutoff.
  Random-like inputs use branchless adjacent merging; non-random inputs preserve the retained
  TimSort-style/adjacent selector.

V7. AVX2 EXPERIMENTAL SIMULATED VARIATION (V2-DERIVED; NO GENERAL FREEZE)
- Header: `include/jessesort/v7_avx2.h`
- Namespace: `jessesort::simulated_simd_v7`
- V2-derived pipeline with a SIMD-oriented capped-probe front end. Default E076 behavior
  caps each game at eight piles during the first 128 values; excess would-be piles spill
  to a temporary probe-overflow run that is sorted and married into an existing pile.
- Exact-eight int32 pile-tail lookup uses one AVX2 compare. E105 adds a narrow repeated
  hint-centered one-register AVX2 continuation for 5k-20k, low-pile layouts (<=12 ordinary
  post-probe piles); broader/global and large-n windowing were rejected. Longer one-shot
  probes and sequential multi-register AVX2 scans remain closed.
- E099 natural-run batching is retained without changing capped-probe behavior on Random.
- E095 fixed the old public-path discrepancy: normalized reconstruction is now the default
  capped-probe reconstruction. E096 then removed its separate `step[]` stream entirely;
  reconstruction improved modestly while whole-sort effect was near neutral.
- E189 restores E162's retained raw non-overflow bulk-span reconstruction to the public V7 call after
  a later call-site omission left the flag at its default false. The original 75% adjacency gate is
  tightened to 95% for the E180C 12-row suite so Sorted+Noise(10%) remains neutral while long-run
  structured rows keep the large raw-span reconstruction win.
- E089 retained bidirectional branchless merging and E093 retained the <=96-byte
  trivially-copyable merge cutoff.
- V7+ numbering remains reserved for SIMD-oriented experiments.

E109 COMMON NON-FREEZING BASELINE — CURRENT POLICY
- E109 intentionally stopped treating historical V1/V2/V3 policy differences as prerequisites
  for further research. Instead it cherry-picked the strongest/recently retained shared policies
  into one common starting point, while preserving the core representation difference of each
  variation.
- Common V1/V2/V3 policies after E109:
    * first-64 `earlyRandomLike` prerequisite for Random branchless merge routing;
    * size-aware density thresholds 3.5 / 4.25 / 5.0 (<=20k / mid / >=500k);
    * descending-game runs materialized before ascending-game runs;
    * E045 final-layout 5/7 gallop selector;
    * E085 bidirectional branchless merge and E093 <=96-byte type gate;
    * adaptive ordered-boundary probing;
    * selective PowerSort-style scheduling when `shouldUsePowerSortMerge()` qualifies.
- V1 remains physical-pile insertion with its own merge driver; V2 remains normalized auxiliary
  reconstruction; V3 remains in-place cycle flattening. E109 copies policies, not entire pipelines.
- Simulated tag encoding remains ascending=0 / descending=1 for now. E109 aligns materialized
  order only; renumbering tags would affect the wider simulated family and is not needed for the
  common V1/V2/V3 baseline.
- E109 is deliberately a CONVERGENCE baseline rather than a claim that every transferred policy
  is locally optimal in every variation. Before/after regressions are recorded below and are now
  explicit follow-up targets.

1.3 CURRENT SHARED ENGINEERING DECISIONS
- Numeric sentinels are removed from maintained implementations.
- Copyable, movable, non-default-constructible values are supported. Move-only values
  remain unsupported because pile-tail mirrors are copied.
- Comparators must provide a strict weak ordering. Inputs containing NaNs require an
  explicit total-order comparator such as NaN-last.
- Equality preserves the current game in maintained pile-routing logic.
- Branchless high-entropy two-run merging is bidirectional across V1-V7 (E085-E089).
- The merge-only fast-path size gate is <=96 bytes for trivially copyable values across
  V1-V7 (E092/E093); this is not a universal element-size policy.
- Natural-run batching is retained across V1-V7 (E098/E099), with stricter activation in
  V5/V6 as described above.
- V4-V6 use 50% as the nominal freeze decision point, with retained power-of-two
  extension policies able to move the actual freeze boundary later.
- Conventional even-sample median retained.
- Random%100 samples uniformly from [0,99]. Sorted+Noise uses 5% independent random
  replacements. Misleading jitter workload removed. BlockSorted handles a partial final
  block safely.

1.4 CURRENT BENCHMARK ARTIFACT POLICY
- `benchmarks/benchmark.cpp` is the canonical whole-sort benchmark.
- Each invocation writes an isolated, gitignored `results/run_*` directory containing
  `benchmark_results.md`, `benchmark_results.csv`, `benchmark_trials.csv`,
  `benchmark_metadata.txt`, and `benchmark_progress.txt`.
- Interrupted runs may be resumed explicitly using the existing run directory; completed
  paired trials are reconstructed from raw CSV and are not rerun.
- Performance decisions use same-run std::sort measurements and paired raw observations.
  Historical CSV collections were removed from the compact repo; decision-relevant
  conclusions remain in this log.

E158 — BIASED DUAL-GAME ASSIGNMENT / PILE-GEOMETRY THROTTLING
- Status: REJECT PRODUCTION CHANGE; RETAIN GEOMETRY EVIDENCE.
- Tested: On Random-like Forced-Patience inputs, preserve the normal first-64 probe, then designate
  one game primary and send an opposite-direction value to the secondary game only every Kth
  opposite event. Exploratory K sweep identified K=16 and K=32 as the most relevant candidates.
- Equivalence guard: The custom K=1 harness was required to match current production V2 blueprint,
  asc/desc counts, and earlyRandomLike exactly before candidate timing was accepted.
- Primary localized method: Resumable per-trial persisted A/B, 500 trials at 10k and 100k and 50 at
  1m. Time insertion, reconstruction, and merge separately; paired deterministic Random inputs and
  alternating execution order. End-to-end Forced-Patience timing is secondary only.
- Geometry: K=16 reduced median pile count ~17-18% at all sizes and left ~3.1% of elements in the
  secondary game. K=32 reduced piles ~20-21% and left ~1.6% in the secondary game.
- Localized timing: K=16 insertion regressed ~26.0% at 10k, ~16.8% at 100k, ~13.7% at 1m;
  reconstruction improved ~2.2%, ~8.1%, ~23.0%; merge improved ~9.2%, ~0.7%, ~1.4%.
  The summed phase ratio remained ~1.072, ~1.062, ~1.032 respectively.
- Localized timing: K=32 insertion regressed ~26.2% at 10k, ~11.1% at 100k, ~14.1% at 1m;
  reconstruction improved ~4.8%, ~9.0%, ~19.8%. At 1m the reduced pile count falls below the
  existing branchless-merge density threshold, so merge becomes ~2.33x slower and the phase-total
  ratio degrades to ~1.75.
- Secondary full-path check: K=16 candidate/baseline median paired ratios were ~1.065 at 10k,
  ~1.053 at 100k, and ~0.989 at 1m. K=32 was ~1.063, ~1.049, and ~1.724.
- Interpretation: High-entropy dual-game fragmentation is real: starving the secondary game can
  remove ~20% of runs. But the dominant game's deeper search chain consumes the benefit, and
  changing run geometry can also cross downstream merge-routing thresholds. This is not a viable
  simple assignment policy.
- Decision: REJECT K-th-event asymmetric throttling as a production mechanism. Do not close
  dual-game geometry research; future work must improve assignment quality while keeping a
  substantive second game rather than approximating single-game Patience.

E173 — INSERTION-TIME IN-PLACE FLATTEN DESTINATION AVAILABILITY
- Status: CLOSED / NO IMPLEMENTATION CANDIDATE; CURRENT V3 LAYOUT DOES NOT EXPOSE ONLINE-FINAL DESTINATIONS.
- Motivation: test whether V3 can overlap some of its expensive post-insertion permutation work with
  pile insertion, without reintroducing E138-style materialization/bookkeeping.
- Layout constraint: V3 materializes descending-game runs first, followed by ascending-game runs.
  For an ascending element, its ordinal inside the pile is known at insertion time, but the pile's
  absolute base depends on the final counts of every earlier run. For a descending element, the
  final within-run position also depends on that pile's final count because descending piles are
  reversed during flattening.
- Diagnostic method: run the exact production V2/V3 insertion path and retain the final blueprint.
  For every element, compute the earliest insertion index at which its absolute V3 destination could
  possibly be certified if an oracle told us exactly when every dependency had received its final
  future element. This oracle is strictly more powerful than any implementable online policy, so
  poor oracle availability is a hard upper bound on useful insertion-time flattening.
- Schedule: canonical int Random, Sorted+Noise, Alternating, Sawtooth, BlockSorted, OrganPipe, and
  Rotated; 500 trials at 10k, 500 at 100k, 50 at 1m; persisted and resumable.
- Key Random result:
    * 10k: 0% known by 50%; ~0.39% by 90%; ~3.48% by 99%; median knowability ~99.99%.
    * 100k: ~0.01% by 50%; ~0.06% by 90%; ~0.48% by 99%; median knowability ~100%.
    * 1m: effectively 0% through 95%; ~0.06% by 99%; median knowability ~100%.
- Other shapes:
    * Sorted+Noise, Alternating, Sawtooth, and OrganPipe are similarly late: essentially nothing can
      be certified until the very end.
    * BlockSorted has a late cliff around ~95% because its small set of long runs finally closes, but
      still provides no useful early overlap.
    * Rotated is the exception: with only two trivial runs, oracle knowability tracks insertion
      progress almost linearly. Rotated is noisy/deprioritized and not a sufficient reason to
      redesign V3 around a special two-run case.
- Interpretation: insertion-time absolute permutation under the current compact contiguous run
  layout is structurally blocked, not merely unoptimized. A safe implementation cannot know that a
  pile is truly closed until future input has been seen, and most destination bases depend on other
  runs that also remain open.
- Decision: CLOSE this direction for the existing V3 layout. Do not add speculative pile-closing,
  rollback, or gap bookkeeping merely to simulate early finality; that would violate the goal of
  eliminating work rather than replacing it with equivalent bookkeeping.
- Future reopening condition: only reconsider if the run layout itself changes (for example reserved
  capacity/gapped run regions) or if a new invariant proves pile closure online.
- Propagation: NOT APPLICABLE; diagnostic only, no production source changed.
- No full V1-V7 benchmark required because no candidate mechanism was implemented or retained.

E175 — V6 ADAPTIVE NATURAL LIVE OVERFLOW RUNS
- Status: REOPENED, REVALIDATED, AND RETAINED. The earlier fixed-width adaptive-band conclusion is
  superseded and removed.
- Reopen reason: the original E175 claimed that 256-element bands helped around 100k but that 1m
  should remain at 32. This was challenged because a larger input appeared to create far more small

- Critical geometry correction:
    * 1m Sawtooth with 32-element bands creates ~7,826 nominal runs before merge, but the production
      ordered-boundary probe immediately collapses them to ~20 actual runs.
    * 256-element bands create ~993 nominal runs but still ~23 after that probe.
  Therefore raw band count is not merge work; most fixed-band boundaries merely subdivide already
  globally ordered overflow stretches and are removed before merging.
- Fixed-width revalidation:
    * Dense sweeps covered bands from 8 through 3,072 and sizes 50k through 2m.
    * 1m 32-vs-64 was raised to 1,000 paired trials and was exactly neutral overall (~1.000x).
    * Mid-size fixed widths showed alignment-sensitive wins (for example 192 at 100k and 384 at
      200k), but the optimum moved with N and failed to extrapolate cleanly. A target of roughly
      128 nominal overflow bands worked through ~300k and then lost as live insertion cost grew.
    * Binary-search + block-move insertion inside larger bands was also tested and rejected; even at
      band 32 it was slower than the existing linear live insertion on the structured overflow order.
- Why fixed widths were unstable: Sawtooth overflow is highly ordered. Diagnostic work counts showed
  zero insertion shifts at 1m for band 32/64, but progressively more shifts as wider bands crossed
  natural overflow resets. Fixed width therefore creates an arbitrary alignment problem.
- Natural-overflow discovery:
    * Sawtooth overflow is exactly five long ascending runs at every tested size (e.g. five runs of
      49,984 values at 1m).
    * 100k BlockSorted overflow typically has only ~1-3 natural ascending overflow runs.
    * 100k Sorted+Noise has hundreds of fragmented overflow runs and ~2,048 normal piles.
  This provides a direct structural selector: low-pile freeze geometry is coherent enough to preserve
  natural overflow runs; high-pile/noisy geometry should keep fixed 32-element live bands.
- Final mechanism:
    * During V6 reconstruction, if overflow exists and normal frozen pile count <=64, append overflow
      values directly while nondecreasing and start a new overflow run only on an actual descent.
    * Otherwise use the historical 32-element live-sorted bands unchanged.
    * This remains architecturally distinct from V4 (one deferred sorted overflow) and V5 (deferred
      bands / recursive-overflow route): V6 still creates multiple overflow runs live during

    * Long monotone structure strongly favors bidirectional natural runs regardless of pile count.

- Deferred chunks:

- Surviving E179 kernel set:
    * clearly ascending, long/high structure -> E175 ascending natural runs;
    * clearly descending or otherwise long monotone structure -> E176 bidirectional natural runs;
    * short/weak/fragmented structure -> fixed live32.
- Router signals remain E177's combined set: overflow fraction + pile geometry/density + first-32
  overflow value transitions. Sample direction alone is explicitly insufficient.
- Production source: unchanged from E177/E176. No full V1-V7 rerun required.

===============================================================================
5. EXPERIMENT / LOG PROCEDURE
===============================================================================

For every future experiment:
1. Update Section 3 with one concise index row.
2. Append ONE compact Section 4 summary containing:
   - hypothesis/mechanism and variation scope;
   - localized benchmark method when decision-relevant;
   - only the important timing deltas/crossovers;
   - retain/reject/inconclusive decision and why;
   - propagation matrix for every applicable variation.
3. Update Section 1 for retained current behavior.
4. Update Section 2 only for genuinely open follow-up work.

Benchmark/decision requirements:
- Exploratory screens may use fewer trials to choose candidates, but they DO NOT justify retain/reject
  when the result is not overwhelming.
- Decision-grade localized A/B uses 500 trials at 10k and 100k and 50 trials at 1m unless the
  experiment documents a reason for a different count. Trials must be paired, deterministic, and
  persisted individually so an interrupted run resumes completed work rather than restarting.
- Localized A/B around the changed mechanism is the PRIMARY performance evidence. If the change also
  changes downstream geometry/routing, time those affected phases separately as well.
- End-to-end timing is SECONDARY confirmation; do not infer mechanism quality from whole-sort timing
  alone.
- Canonical acceptance after a RETAIN remains V1-V7 at 1k/10k/100k/1m with 500/500/500/50 trials,
  paired deterministic seeds, resumable persisted runs, and correctness validation.
- PERMANENT REGRESSION-AUDIT REQUIREMENT: the full acceptance suite is not complete until its timing
  results are compared against the immediately preceding authoritative accepted baseline for every
  V1-V7 x canonical-input cell. Report old microseconds, new microseconds, and new/old ratio. The
  purpose of the full suite is both correctness validation and detection of unintended performance
  regressions outside the targeted mechanism.
- Automatically flag for investigation any acceptance cell slower by >3% at 10k or 100k, or >5% at
  1k or 1m. These are investigation thresholds, not automatic reject thresholds: rerun each flagged
  cell under matched conditions (500 trials at 10k/100k; appropriate canonical count at 1k/1m, and
  increase sampling when needed) to determine whether the movement is reproducible or timing/layout
  noise. Do not finalize retain/accept until every material flag is resolved and documented.
- Always inspect Random separately in the regression audit even when the candidate should not affect
  Random. Also investigate any conspicuous cross-variation movement on paths that should be unchanged,
  since that can reveal code-layout, build-lineage, or harness contamination.
- Use same-binary/layout-matched A/B where compiler cloning, buffer placement, or allocator effects can
  create false deltas. Alternate physical buffer ownership as well as execution order when relevant.
- Small effects need proportionally stronger evidence. Do not let a lightly sampled whole-sort result
  overrule a large, stable localized win without resolving the disagreement.
- Keep rejection taxonomy: MECHANISM REJECTED, INTEGRATION REJECTED, or POLICY/STALE-DEPENDENT REJECTED.
- Do not compare absolute timings across different hosts/runs as causal evidence.

Propagation requirements (strengthened by E156):
- A retained change is not finalized until every applicable variation is explicitly resolved as
  PROPAGATED+TESTED, TESTED+REJECTED, NOT APPLICABLE, or INTENTIONALLY DIFFERENT.
- A full benchmark alone does not prove propagation.
- When variations are controlled comparisons, share code around the intentional difference and add
  parity checks for the shared state/policy.
- Any deliberate divergence must cite the experiment that measured and retained it.

Checkpoint / recoverability requirement:
- After EVERY completed experimental test or materially changed harness/candidate state, create a
  downloadable repository checkpoint containing the source/harness and any persisted partial/final
  result files needed to reproduce or resume the experiment, and share the link before beginning the
  next test. This is mandatory because execution environments may be lost between turns.
- Keep resumable result files isolated by experiment/size/policy so stale outputs cannot be mixed into
  later summaries.

Log hygiene:
- Do not append shell transcripts, build commands, temporary file paths, documentation-edit histories,
  or stale next-step plans.
- Do not preserve giant benchmark tables once a later baseline supersedes them; retain the meaningful
  ratio/percentage and crossover that justified the decision.
- If an old result becomes irrelevant after major architectural change, keep only its historical
  decision/mechanism and mark it superseded where appropriate.

- Goal: resolve the second low-hanging-fruit checkpoint before the V8 linked-blueprint study: determine
  whether the current dual-game insertion code still exposes an untested O(1)/single-search assignment
  signal that could reduce pile fragmentation without paying a second pile search.
- Method: source/log audit only. Inspected the current V1-V7 assignment state and the completed E139,
  E158, E159, E169, E171, E181, E183, and E185 mechanisms. No production source was modified and no
  timing benchmark was warranted because no genuinely new low-cost mechanism survived the audit.
- Current free state available to ownership decisions: local previous/current direction; last-used pile
  index for ascending and descending games; existing tail-array boundaries including pile 0 / outer pile;
  first-64 probe geometry; and E183's one-value lookahead for structurally gated strict valleys.
- Already tested/dispositioned uses of that state: single-game pressure observation (E139); asymmetric
  throttling/sustained-direction policies (E158); outer-quarter opposite-game second search (E159); O(1)
  opposite last-pile/pile-0 rescue (E169); sampled block routing (E171); short-prefix boundary ownership
  (E181); gated valley-to-ascending rescue (E183 retained); peak-to-descending reassignment (E185 rejected,
  with peaks intentionally remaining ascending).
- Finding: there is no remaining obvious O(1)/single-search dual-game policy. A stronger assignment rule
  would require a materially new ingredient such as a second opposite-game pile search, broader natural-run
  lookahead, or new maintained cross-game state. Those are architectural/new-hypothesis work, not quick
  cleanup.
- Decision: COMPLETE / NO CODE CHANGE. Mark the dual-game assignment TODO DORMANT. Keep E183's asymmetric
  ownership rule and ordinary direction-selected assignment. Reopen only when a concrete materially new
  mechanism exists; do not keep generating threshold variants of closed policies.
