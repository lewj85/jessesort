  variable monotone run lengths around it with randomized direction/range/step. This keeps both run count

1.2A PRE-E225 LEGACY V1-V11 REFERENCE (HISTORICAL)

CANONICAL IDENTITY QUICK REFERENCE
- V1-V3 are NON-FREEZING designs. V4-V6 are the EARLY-FREEZE/OVERFLOW designs.
  V7 is a V2-derived SIMD/capped-probe research path and is not part of the freeze family.
  V8 and V9 are maintained research families for linked-blueprint locality and index-tail genericity.
  V10 and V11 are the allocation-free branch: V10 is the narrow bounded/fallback baseline;
  V11 adds a shared physical tail pool and selective low-run general in-place merging.

  V1  Actual physical piles                  no freeze      no overflow
  V2  Simulated blueprint                    no freeze      no overflow
  V3  V2-style simulation + in-place flatten no freeze      no overflow
  V4  Early freeze + single deferred run     freeze family  one large overflow run
  V5  Early freeze + deferred bands          freeze family  32-element deferred bands
  V6  Early freeze + adaptive live overflow  freeze family  fixed32 / natural asc / bidir natural
  V7  V2-derived AVX2 capped-probe path      no general freeze; temporary probe spill only
  V8  Linked-blueprint locality family       no freeze      linked element/span reconstruction
  V9  Index-tail genericity family           no freeze      move-only-capable generic Patience path
  V10 Allocation-free bounded family         fixed caps      no-heap Jesse front end + in-place fallback
  V11 Allocation-free shared-tail merge       fixed caps      shared 127-tail pool + gated live run-stack reclamation

- E050 is the canonical numbering reset. Detailed historical records have been translated
  to these implementation identities where practical; old artifact FILENAMES may still
  contain pre-E050 labels and must be interpreted by namespace/implementation identity.

CANONICAL DIFFERENCE BREAKDOWN — V1 THROUGH V11
- V1: literal vector-backed physical Patience piles. No freezing. This is the physical-pile representation baseline.
- V2: simulated Patience using value-tail metadata + packed 32-bit blueprint tags, followed by streaming auxiliary reconstruction. No freezing. This is the primary speed-oriented simulated baseline.
- V3: controlled V2 reconstruction/memory variation. It intentionally shares V2 insertion/topology but resolves the blueprint by in-place permutation-cycle flattening. No freezing; do not route away the in-place flatten merely because E157 shows it is often slower.
- V4: early-freeze family with one large deferred overflow run. Ordinary pile creation freezes around the retained 50% decision policy, then overflow is gathered contiguously and sorted as one run.
- V5: early-freeze family with deferred 32-element overflow bands. Bands remain unsorted during insertion and are sorted during reconstruction; exact full bands use the retained specialized 32-element network.
- V6: early-freeze family with live/adaptive overflow handling. Weak structure uses live 32-element bands; clearly ascending low-pile structure uses ascending natural runs; other strong directional cases may use bidirectional natural runs.
- V7: V2-derived SIMD research path. It caps the initial probe to a small pile count (default eight piles/game over the first 128 values), uses temporary probe spill, and specializes exact-eight int32 tail lookup with AVX2. It is not a general freezing variation.
- V8: linked-blueprint locality family. Whenever Patience reconstruction is reached, reconstruction remains linked: E201 selects compact span links for low-fragmentation blueprints or in-place element links otherwise, with first-merge fusion. Specialized direct backends/monotone exits may bypass Patience normally, but V8 does not use ordinary V2 tag reconstruction merely to hide linked costs.
- V9: index-tail/genericity family. Pile-tail metadata stores source indices and compares through the untouched source instead of storing copies of T. This enables the move-only/non-copyable path. Copyable V9 may reuse V2's optimized reconstruction/merge after blueprint creation; the defining index-tail mechanism must remain intact.
- V10: allocation-free bounded baseline. Fixed 63-asc + 64-desc source-index tails, <=64 fixed run descriptors, no O(n) blueprint/T scratch, and no heap allocation inside sort. Only cheap bounded run geometries are handled by Jesse reconstruction; unsupported shapes fall back to allocation-free partition/heapsort. E210 reduces peak explicit fixed metadata to 2,560 B plus scalar locals/call stack on the current 64-bit build.
- V11: allocation-free shared-tail + selective in-place merging. Uses one physical 127-index tail pool but **retains the current logical 63/64 split**; E213's adaptive split is not retained. E216 added geometry-gated general in-place merging for suitable <=64-run layouts. E217 extends that path past 64 natural runs by live bounded run-stack reclamation: when the fixed 64 descriptors fill, the smallest adjacent completed pair is normalized/merged in place to reclaim one descriptor. A first-65 preflight requires average run length >=1024 and rejects repeated-overlap/Sawtooth-like geometry, preserving fallback for short/high-entropy or movement-heavy cases.

IDENTITY GUARDRAIL
- Reminder that these all changed from V# names to names with descriptive tags starting with E229.
- These numbers name architectural experiments, not merely whichever policy is fastest today. Preserve each variation's defining mechanism when benchmarking it: V3 keeps in-place flattening, V8 stays linked after Patience reconstruction, V9 keeps index tails, V10 remains the narrow bounded/fallback no-heap control, and V11 remains the shared-tail + selective low-run-merge extension. 1.3 CURRENT SHARED ENGINEERING DECISIONS
- Numeric sentinels are removed from maintained implementations.
- V1-V8 (under pre-E229 naming) require copyable + movable values in their current implementations because some
  metadata paths store values by copy. V9 uses index tails and a non-copyable reconstruction path, so V9 supports
  move-only, non-default-constructible values while still requiring move construction/assignment. V10 and V11 also
  support movable non-copyable values and, by identity, perform no heap allocation inside the sort.
- Comparators must provide a strict weak ordering. Default floating-point `<` is not supported for NaN-containing
  inputs; use an explicit NaN-aware strict-weak-order comparator, such as a total-order/NaN-last comparator.
- Equality preserves the current game in maintained pile-routing logic.
- Branchless high-entropy two-run merging is bidirectional across V1-V7 (E085-E089).
- The merge-only fast-path size gate is <=96 bytes for trivially copyable values across
  V1-V7 (E092/E093); this is not a universal element-size policy.
- Natural-run batching is retained across V1-V7 (E098/E099), with stricter activation in
  V5/V6 as described above.
- V4-V6 use 50% as the nominal freeze decision point, with retained power-of-two
  extension policies able to move the actual freeze boundary later.
- Conventional even-sample median retained.
- Random%100 samples uniformly from [0,99]. Sorted+Noise uses 5% independent random
  replacements. Misleading jitter workload removed. BlockSorted handles a partial final
  block safely.

E225 — V2 BOUNDED LONG-NATURAL-RUN DIRECT ROUTE — RETAINED
-----------------------------------------------------------------------
- Goal: produce a high-impact V2 speedup by removing whole Patience/blueprint/reconstruction phases on inputs
  that are already a small sequence of long natural runs, without using canonical generator identities or
  numeric-domain properties. CPU: AMD EPYC 9V74 80-Core Processor; GCC 14.2.0; C++20 -O3 -march=native -DNDEBUG.
- Final route, before V2 Patience insertion and only for n>=10k: require the first 64 values to be nondecreasing under
  `Less`; require at least one inversion in nine evenly spaced coarse samples so fully Sorted returns to existing V2;
  then perform a mutation-free natural-run preflight into fixed `NaturalRun[128]`. If a 129th run would be needed,
  reject before mutation. If accepted, reverse descending natural runs, collect their ends, and merge them directly
  with V2's existing O(n) auxiliary merge storage. The route is comparator-defined and supports custom strict-weak
  orderings; it does not inspect key ranges/cardinality/seeds.
- Mechanism screen: unconditional direct natural-run merging showed large headroom but was bad on Alternating and
  Noise10, motivating the generic structural router. The final <=128-run preflight also prevents the adversarial
  `64 sorted values + random suffix` case from entering the route.
- Final source-integrated causal A/B, frozen pre-E225 V2 -> candidate, order-neutral ratios:
    * 10k: Sawtooth 0.663, Mixed 0.918, Block 0.276, OrganPipe 0.583, Rotated 0.276.
    * 100k: Sawtooth 0.721, Mixed 0.506, Block 0.340, OrganPipe 0.674, Rotated 0.483.
    * 1m x50: Sawtooth 0.739, Mixed 0.938, Block 0.412, OrganPipe 0.663, Rotated 0.513.
  Mixed is intentionally partial because only its ascending-prefix subset enters E225. Exact us and raw A/B evidence
  are under `benchmarks/baselines/e225/`.
- Genericity/safety: a 100k adversarial 64-sorted-prefix/random-suffix input was rejected before mutation; a
  non-default-constructible record using a custom descending comparator entered the route and sorted correctly.
- Regression audit: same-binary duplicate template instantiation can visibly perturb inactive rows (e.g. Reverse), so
  those flags were not dismissed. A fresh exact-frozen 10k full-suite baseline and three separate-build 1m repeats
  were used to isolate dispatch/code-layout cost. Reverse was essentially identical in every separate-build repeat;
  Random/Noise/Alternating varied in both directions with no reproducible candidate penalty. Random was explicitly
  reviewed. Earlier old-session full-suite comparisons also moved unchanged V1-V11 cells together and were treated
  as host/session evidence rather than causal E225 deltas.
- Full acceptance: final bounded candidate completed canonical V1-V11 + std::sort, all 12 workloads, 500 trials at
  1k/10k/100k and 50 at 1m, with no correctness failures. Final production V2 medians include 100k Sawtooth
  655.109 us, Mixed 133.478 us, Block 81.572 us, OrganPipe 144.610 us, Rotated 39.860 us; 1m respective medians
  7.287/4.514/1.762/2.302/1.149 ms. Full tables and compressed raw trials are preserved in the E225 baseline folder.
- Propagation audit: V2 = PROPAGATED+TESTED+RETAINED. V1 and V3-V11 = INTENTIONALLY DIFFERENT / NOT APPLICABLE
  for E225 propagation because this is a V2 public-wrapper pre-router that bypasses the variations' defining
  insertion/reconstruction mechanisms. All eleven variations were still TESTED in full acceptance.
- Decision: RETAIN E225. Do not tune the 64/9/128 gates as a micro-study next; move to phase measurement of the
  remaining Random/Noise paths for the next high-impact experiment.
