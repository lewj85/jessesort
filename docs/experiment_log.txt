EXPERIMENT DECISION POLICY
- Use REJECT only when a mechanism is broadly inferior, causally unsound, or no practically useful regime survives validation.
- If a candidate has a substantial/repeatable win in a meaningful regime but loses elsewhere, mark it PROMISING / MORE ANALYSIS NEEDED rather than rejecting it. Test simple general routing variables already available to the algorithm (especially n, sizeof(T), run/pile count, or an existing structural signal) before closing it.
- A size threshold is legitimate when a crossover is stable across intermediate/OOD sizes; exact canonical-size checks are not. A non-monotone crossover means size alone is insufficient, not that the underlying mechanism should be discarded.
- Preserve promising experimental implementations/results even when they are not yet production-retained, and record the next discriminating experiment explicitly.
- Preserve what affects future decisions: mechanism tested, variation scope, retain/reject status,
  meaningful speedups/regressions, crossover thresholds, and why a result mattered.

  make them non-comparable.
- Old percentage/ratio results are historical causal evidence, not current performance claims.

1.1 BENCHMARK AND AUDIT STANDARD
- E077 introduced the whole-sort benchmark methodology; E100 centralizes its deterministic seed policy.
- E319 reduced the routine benchmark roster to seven Jessesort variants plus `std::sort`; architecturally interesting non-routine headers remain preserved under `include/jessesort/experimental/`.
- E320 retired multi-variation timing inside one benchmark process after proving that related variants could warm a shared backend for one another and move a bimodal median.
- E323 removed the pre-timing reference-sort bias and defined warm-state steady-throughput. E337 closes the infrastructure audit by isolating every **algorithm × canonical-input cell** in its own process, randomizing/logging all cell order, keeping reference `std::sort` after timing, and making fixed CPU affinity canonical when `taskset` is available. E337 was necessary because algorithm-only isolation still allowed fixed workload order and unpinned scheduler/frequency bimodality to move short-input medians.
- Canonical `make bench` profile (E466 runner cleanup):
    * C++20, -O3, -march=native, -DNDEBUG
    * routine set = 8 Jessesort descriptors + independently timed `std::sort`
    * default n = {10k, 100k} only; 1k/1m require explicit direct invocation and are never selected by the routine runner
    * 2 untimed warmups per size/algorithm/input process
    * 500 measured independent trials per cell in one uninterrupted process after warmups
    * every size × algorithm × input is a separate process; one deterministic unique seed per trial
    * the suite records and enforces exact CPU model plus benchmark/source fingerprints on resume
    * active-cell rows stay quarantined under `in_progress/`; interrupted cells are discarded and rerun from trial 0
    * each fully validated cell is atomically committed; 100k refreshes the cumulative ZIP after every cell, while 10k refreshes once after all 14 inputs for the current algorithm to avoid checkpoint overhead dominating short cells
- CACHE/PROCESS POLICY:
    * Do **not** use Linux `drop_caches` as a CPU-cache flush; it targets filesystem page cache/dentries/inodes, not L1/L2/L3/BTB/TLB state.
    * Do **not** add a giant userspace eviction buffer to the canonical benchmark. That changes the workload into an artificial cold-cache/memory-pressure test and still cannot normalize instruction cache, branch predictor, TLB, or heterogeneous shared-cache topology.
    * Residual hardware state from a previous child may survive process exit, but it is consumed by the next cell's untimed algorithm/input-specific warmups before measured trials. The benchmark intentionally measures warmed steady behavior.
    * The source vector is copied immediately before the timer, so input data is intentionally hot in a consistent way across algorithms.
    * Every size × algorithm × input cell is a separate process. Cell order is randomized and recorded to prevent permanent algorithm or workload identity correlation with long-timescale host/thermal/frequency drift. The default one-second cooldown is a thermal/frequency settling aid, not a claimed cache flush.
    * Canonical runs auto-pin children to the first CPU in the runner's allowed affinity mask when `taskset` is available; override with `BENCH_CPU=<cpu>` or disable with `BENCH_CPU=none`. E337 promoted pinning from optional to canonical after it collapsed a strong unpinned Random%25 bimodality.
    * CPU frequency, thermal state, interrupts, VM contention, and host migration remain external noise sources. Close decisions still require same-session controls and repeated confirmation.
- VALIDATION POLICY:
    * Correctness validation remains outside timed regions.
    * The reference `std::sort` used for exact-output validation runs after the timed algorithm. This removes the E323-discovered bias where the `std::sort` control was always timed as a second back-to-back `std::sort`, and every Jessesort timing immediately followed a full reference sort.
- CPU REPORTING IS MANDATORY FOR EVERY TIMED TEST: copy the exact CPU model reported by `/proc/cpuinfo` / benchmark metadata into the experiment-log entry alongside timing evidence. Do this for localized harnesses as well as full canonical sweeps. Hosted sessions may migrate between CPU models, so an experiment without its CPU recorded is not a safe longitudinal timing reference.
- E204 established that unchanged code can move materially across CPU models; historical absolute microseconds are therefore not longitudinal baselines. Record CPU/compiler with every timed result and use matched-session controls for causal comparisons.
- E205's rotating same-process order policy is **superseded** by E320/E323 for cross-variation timing. E205 remains useful evidence that benchmark context itself can move timings, but it is no longer the canonical process model.
- PRE-E323 TIMING PROVENANCE:
    * Pre-E320 timing comparisons that placed related algorithms in one process are susceptible to shared-backend cache/predictor/order contamination. Structural/correctness evidence remains valid; small timing-derived decisions are provisional until audited.
    * E320-E322 removed same-process cross-variation contamination, but still performed an untimed reference `std::sort` before each timed call and ran child algorithms in a fixed shell order. Large architectural effects remain useful; close ratios versus `std::sort` and near-noise-floor variation differences remain provisional.
    * Do not rewrite old experiment history. Mark retained decisions as revalidated, structurally safe, superseded, or still provisional as the audit proceeds.
- MANDATORY POST-CHANGE ACCEPTANCE RULE: test only the maintained variation(s) whose executable sorting behavior is affected by the change. A one-variation change requires canonical acceptance only for that variation. If that variation imports/consumes changed logic from another maintained variation, test the dependent/source variation too; this normally means at most two variations, not the full routine bank.
- Every performance-change evaluation must preserve the canonical timing/distribution evidence for the affected variation(s). Localized/phase harnesses remain the primary causal test; the affected-variation canonical run is the repository-level acceptance check. A full routine-bank sweep is optional infrastructure/periodic validation, not a retention prerequisite for a narrowly scoped algorithm change.
- AFFECTED-VARIATION REGRESSION AUDIT: acceptance is not complete until every canonical timing cell for each affected variation at every tested size is compared against an immediately rerun same-session control using independent-process medians and distributions. Any apparent regression >1.0% must be investigated before retention. Repeat flagged cells under matched conditions and inspect p25/p75, IQR, MAD, and trial distributions rather than deciding from one median.
- For close A/Bs, candidate and control must not be timed sequentially in the same process on the same trial input. Prefer separate candidate/control processes or separately built binaries with identical seed schedules. Same-binary/phase harnesses may still be used for structural diagnosis or untimed counters, but not as sole evidence for a small whole-sort retain decision.
- E405 HOST-BIMODALITY GUARDRAIL: on hosted CPUs, identical code can occupy distinct execution-speed modes for long contiguous trial bursts even under fixed CPU affinity. If an inactive/null path moves >1% or a fast cell is visibly multimodal, a one-shot process median is not decision-grade. Repeat independently launched candidate/control cohorts with identical seed schedules and alternating process order; make the decision from the distribution/median of process-level ratios, and use inactive rows to estimate common-mode movement. Do not attribute null-path movement to the code change.
- When a canonical affected-variation run conflicts with a smaller causal harness, treat the causal harness as mechanism evidence and the isolated canonical run as repository-level acceptance evidence; investigate rather than allowing either one to silently overrule the other.
- Targeted numeric-size invocations use the requested trial count directly; they do not automatically apply the 1m 10:1 reduction.
- Canonical seed policy for normal benchmarks and one-off A/B tests:
    * base seed: `jessesort::bench::kCanonicalBaseSeed` (0x8A5CD789)
    * mixer: `jessesort::bench::trial_seed()` in `benchmarks/benchmark_seed.h`
    * do not invent a new seed population for an ordinary one-off test; explicitly label intentional held-out/confirmation cohorts instead.
- Preserve raw per-algorithm timings. Report median, p25/p75, IQR, MAD, and ratio of independent medians as appropriate; do not silently trim outliers. Paired cross-algorithm trial ratios are not part of the canonical benchmark.
- Full rationale and remaining limitations: `docs/benchmark_methodology.md`.
- Baseline workload families (frozen in E180C): Random, Sorted, Reverse, Sorted+Noise(5%),
  Sorted+Noise(10%), Random%25, Alternating, Sawtooth, MixedDirectionRuns, BlockSorted, OrganPipe,
  and Rotated. E228 adds two permanent router-safety phase-change families without modifying any of
  those 12 generators: MixedPhase3 = Sorted+Noise(5%) -> MixedDirectionRuns -> Random in three
  contiguous near-equal phases; MixedPhase12 = the 12 frozen baseline families once each in baseline
  order in 12 contiguous near-equal phases. Current acceptance therefore covers 12 frozen baseline
  families + 2 router-safety families. Synthetic diagnostics outside these 14 may explain mechanisms
  but may not tune production policy unless first promoted to the permanent benchmark suite.

Resume occurs only at committed measurement units: an interrupted 500-trial cell is discarded and rerun from trial 0 with fresh warmups, while completed cells are never rerun. CANONICAL DIFFERENCE BREAKDOWN - `physical` THROUGH `noalloc-low-run`
- `physical`: literal vector-backed physical Patience piles. No freezing. This is the physical-pile representation baseline.
- `simulated`: simulated Patience using value-tail metadata + packed 32-bit blueprint tags, followed by streaming auxiliary reconstruction. No freezing. This is the primary speed-oriented simulated baseline.
- `simulated-inplace`: controlled `simulated` reconstruction/memory variation. It intentionally shares `simulated` insertion/topology but resolves the blueprint by in-place permutation-cycle flattening. No freezing; do not route away the in-place flatten merely because E157 shows it is often slower.
- `frozen-single`: early-freeze family with one large deferred overflow run. Ordinary pile creation freezes around the retained 50% decision policy, then overflow is gathered contiguously and sorted as one run.
- `frozen-deferred`: early-freeze family with deferred 32-element overflow bands. Bands remain unsorted during insertion and are sorted during reconstruction; exact full bands use the retained specialized 32-element network.
- `frozen-live`: early-freeze family with live/adaptive overflow handling. Weak structure uses live 32-element bands; clearly ascending low-pile structure uses ascending natural runs; other strong directional cases may use bidirectional natural runs.
- `avx2`: `simulated`-derived SIMD research path. It caps the initial probe to a small pile count (default eight piles/game over the first 128 values), uses temporary probe spill, and specializes exact-eight int32 tail lookup with AVX2. It is not a general freezing variation.
- `linked`: linked-blueprint locality family. Whenever Patience reconstruction is reached, reconstruction remains linked: E201 selects compact span links for low-fragmentation blueprints or in-place element links otherwise, with first-merge fusion. Specialized direct backends/monotone exits may bypass Patience normally, but `linked` does not use ordinary `simulated` tag reconstruction merely to hide linked costs.
- `indexed`: index-tail/genericity family. Pile-tail metadata stores source indices and compares through the untouched source instead of storing copies of T. This enables the move-only/non-copyable path. Copyable `indexed` may reuse `simulated`'s optimized reconstruction/merge after blueprint creation; the defining index-tail mechanism must remain intact.
- `noalloc`: allocation-free bounded baseline. Fixed 63-asc + 64-desc source-index tails, <=64 fixed run descriptors, no O(n) blueprint/T scratch, and no heap allocation inside sort. Only cheap bounded run geometries are handled by Jesse reconstruction; unsupported shapes fall back to allocation-free partition/heapsort. E210 reduces peak explicit fixed metadata to 2,560 B plus scalar locals/call stack on the current 64-bit build.
- `noalloc-low-run`: allocation-free shared-tail + selective in-place merging. Uses one physical 127-index tail pool but **retains the current logical 63/64 split**; E213's adaptive split is not retained. E216 added geometry-gated general in-place merging for suitable <=64-run layouts. E217 extends that path past 64 natural runs by live bounded run-stack reclamation: when the fixed 64 descriptors fill, the smallest adjacent completed pair is normalized/merged in place to reclaim one descriptor. A first-65 preflight requires average run length >=1024 and rejects repeated-overlap/Sawtooth-like geometry, preserving fallback for short/high-entropy or movement-heavy cases.
- `simulated-phase-map`: E250 large-N phase-map plant. A cheap endpoint route-diversity gate decides whether to pay for x2 galloping 32-value dual-Patience observations capped at 8k; confirmed changes use 75%-late no-lookback boundaries. Each mapped region is then sorted by a fresh ordinary `simulated` decomposition and the runs are merged. The reference implementation copies mapped chunks.
- `simulated-phase-map-range`: E251 zero-copy execution plant. Mapping/gating/boundaries match `simulated-phase-map`, but mapped regions use a phase-map-local range-capable `simulated` engine on `std::span<T>` and avoid the copy-in/copy-back layer. Fresh `simulated` remains its default mapped-region backend.
- `simulated-phase-map-range-transition-partition`: E255 conservative backend-specialized descendant. It keeps E251 mapping/boundaries/execution intact, but when a stored ENTROPY region independently observes `(STRUCTURED, ENTROPY, ENTROPY)` at lead/mid/tail it bypasses fresh `simulated` and uses the existing high-entropy partition backend. The override is specialized-integral-only and otherwise falls back to E251 behavior.
- `simulated-phase-map-range-transition-partition-body-entropy`: E256 broader transition descendant. It preserves E255's stored-ENTROPY + STRUCTURED-lead + ENTROPY-midpoint mechanism but accepts any non-STRUCTURED tail, adding the independently validated `(STRUCTURED, ENTROPY, OTHER)` cohort. E255 remains the conservative control.

IDENTITY GUARDRAIL
- E229 replaced the former opaque numbered names with the descriptive short tags used below.
- These tags name architectural experiments, not merely whichever policy is fastest today. Preserve each variation's defining mechanism when benchmarking it: `simulated-inplace` keeps in-place flattening, `linked` stays linked after Patience reconstruction, `indexed` keeps index tails, `noalloc` remains the narrow bounded/fallback no-heap control, and `noalloc-low-run` remains the shared-tail + selective low-run-merge extension. `physical`. ACTUAL PHYSICAL PILES
- Header: `include/jessesort/jessesort_physical_probe-routed_adjacent-adaptive-buffered.h`
- Representation: vector-backed physical patience piles with separate tail mirrors.
- Early routing: equality preserves the current game. A >=32-element monotone prefix is
  materialized directly. Otherwise the true first-64 probe routes Random-like inputs to
  direct bit-walk tail search, high-locality inputs to exact previous-pile hint + binary
  fallback, and ambiguous inputs to ordinary binary search (E046/E047/E056).
- E099 natural-run route: after an initial monotone prefix covering >=12.5% of n, later
  strict runs of length >=8 whose endpoints resolve to one physical pile are appended in
  bulk. This is retained and especially effective for OrganPipe/Rotated.
- E109 convergence baseline: `physical` now uses the same non-freezing Random merge predicate as `simulated` / `simulated-inplace`:
  the first-64 `earlyRandomLike` signal + common 3.5/4.25/5.0 pile-density thresholds + the
  <=96-byte trivially-copyable type gate. The older `physical`-only minority-game balance predicate is
  no longer part of the common starting policy.
- Merge kernel: E083 raw pointers + E085 bidirectional low/high-end branchless merge are retained.
- E111 removed selective PowerSort from the common `physical` / `simulated` / `simulated-inplace` policy after cross-variation revalidation.
- E115 consolidates `physical` / `simulated` / `simulated-inplace` onto one shared ends-based adjacent-pair post-flatten merge driver with
  adaptive ordered-boundary probing and the retained E045/E085 routing/kernel choices.

`simulated`. SIMULATED BLUEPRINT
- Header: `include/jessesort/jessesort_simulated_probe-routed_adjacent-adaptive-buffered.h`
- Representation: sentinel-free value tails plus packed 32-bit blueprint tags.
- Early insertion routing: >=32 monotone-prefix recognition; first-64 structure signal;
  one-time no-hint continuation for sustained Random-like structure; split exact-hint
  path for >=75% hint locality; ordinary search otherwise (E043/E065).
- E402 propagates E354's small-N three-pile exception to ordinary `simulated`: below 32k, a perfectly nondecreasing first-64 probe producing exactly three piles skips E183 valley rescue.
- E098 natural-run route: if the initial strict monotone prefix covers >=12.5% of n,
  later strict runs of length >=8 are endpoint-tested and blueprint-tagged in bulk when
  both endpoints map to the same pile. Exact blueprint/count/tail equality was required
  in A/B validation.
- Reconstruction: descending-game runs first, ascending-game runs second. E081 normalizes
  packed local tags to global run IDs before scatter. E086 keeps an explicit `step[]`
  table below 500k and derives direction from normalized run ID at >=500k, where the
  metadata-stream reduction wins.
- E109 convergence baseline replaces `simulated`'s old pre-E085 E053 density coefficients with the shared
  non-freezing 3.5/4.25/5.0 thresholds. `simulated` keeps its `earlyRandomLike` prerequisite, E045 gallop
  selector, and adaptive ordered-boundary probing. E101 previously removed the obsolete E063 per-pair
  imbalance fallback. E111 removed selective PowerSort; E115 moves `simulated` onto the same shared ends-based
  adjacent-pair post-flatten merge driver used by `physical`/`simulated-inplace`.
- High-entropy merge: E082 raw pointers + E085 bidirectional branchless merging retained.
  E092 widened the merge-only trivially-copyable type cutoff through 96 bytes; 128 bytes
  crossed to neutral/slower. Do not infer the same cutoff for insertion copies.
- E225 adds a `simulated`-champion-only bounded natural-run direct route before Patience insertion for n>=10k.
  It uses only comparator-defined structure: first 64 values nondecreasing, at least one inversion in
  a 9-point coarse sample, and a mutation-free preflight of <=128 natural runs. Accepted inputs normalize
  descending runs and merge the natural runs directly with `simulated`'s existing O(n) auxiliary merge storage;
  >128-run inputs fall back to the unchanged Patience path before mutation. This is a generic structural
  route, not a value-domain specialization. E227 later propagates this same public-wrapper route to the other
  allocating variations `physical` and `simulated-inplace` through `indexed`; `noalloc` / `noalloc-low-run` intentionally remain separate because E225 uses O(n) scratch.

1.3 CURRENT SHARED ENGINEERING DECISIONS
- Numeric sentinels are removed from maintained implementations.
- `physical`, `simulated`, `simulated-inplace`, the frozen families, `avx2`, `linked`, and the phase-map families require copyable + movable values in their current implementations because some
  metadata paths store values by copy. `indexed` uses index tails and a non-copyable reconstruction path, so `indexed` supports
  move-only, non-default-constructible values while still requiring move construction/assignment. `noalloc` and `noalloc-low-run` also
  support movable non-copyable values and, by identity, perform no heap allocation inside the sort.
- Comparators must provide a strict weak ordering. Default floating-point `<` is not supported for NaN-containing
  inputs; use an explicit NaN-aware strict-weak-order comparator, such as a total-order/NaN-last comparator.
- Equality preserves the current game in maintained pile-routing logic.
- Branchless high-entropy two-run merging is bidirectional across `physical` through `avx2` (E085-E089).
- The merge-only fast-path size gate is <=96 bytes for trivially copyable values across
  `physical` through `avx2` (E092/E093); this is not a universal element-size policy.
- Natural-run batching is retained across `physical` through `avx2` (E098/E099), with stricter activation in
  `frozen-deferred` / `frozen-live` as described above.
- `frozen-single`, `frozen-deferred`, and `frozen-live` use 50% as the nominal freeze decision point, with retained power-of-two
  extension policies able to move the actual freeze boundary later.
- Conventional even-sample median retained.
- Random%100 samples uniformly from [0,99]. Sorted+Noise uses 5% independent random
  replacements. Misleading jitter workload removed. BlockSorted handles a partial final
  block safely.

1.4 CURRENT BENCHMARK ARTIFACT POLICY
- `benchmarks/benchmark.cpp` is the canonical whole-sort benchmark and `make bench` / `benchmark.sh` is the routine 10k+100k entrypoint.
- Canonical suite state lives under the current results root with committed `cells/`, quarantined `in_progress/`, suite metadata, aggregate tables, and cumulative checkpoint ZIPs. Historical raw timing trees are pruned from the slim repo once their decision-relevant conclusions are consolidated here.
- A 500-trial cell is atomic: partial active-cell output is never merged with a later process. If interrupted, discard that cell and rerun it from trial 0; completed cells remain committed. At 10k the ZIP checkpoint is refreshed after all 14 inputs for an algorithm; at 100k it is refreshed after every cell.
- Performance decisions use one algorithm/input cell per process under the warm-isolated methodology. `std::sort` is an independently timed control; correctness reference sorting occurs after the timed call. Close audit decisions use repeated independent process medians rather than same-process paired observations.
- Test only variations whose executable behavior changes; include an imported dependency/source variation only when its behavior is affected.
- Every retained performance change requires canonical affected-variation acceptance, CPU/compiler context, >1% regression investigation, propagation disposition, and a ZIP checkpoint.
- **Evidence-integrity hard gate (E364):** never combine raw timings, medians, or ratios from different benchmark cohorts in one result row. Every displayed ratio must be machine-recomputed from the raw values in that same cohort/artifact; if a second cohort is useful, show it separately and label it separately.
- A decision-eligible experiment artifact must preserve raw trial timings, deterministic seed/trial IDs, benchmark method/version, CPU/compiler context, source + executable hashes, and the exact derivation script. Summary-only or ratio-only CSVs are supporting evidence only and cannot by themselves justify RETAIN/REJECT.
- Experiment-specific harnesses must include reachability/negative-control checks when the candidate is conditional. If a candidate-inactive cell moves >1%, treat that cohort as contaminated for causal inference until repeated independent pinned-process rechecks resolve it; do not rationalize the delta as layout/noise while retaining from the same cohort.
- For small/medium effects or noisy hosts, use repeated independent pinned processes with alternating control/candidate process order and base decisions on the median across process medians. Same-process paired timing may diagnose causality but is not the sole retention evidence when cache/predictor carryover is possible.
- For deterministic varying-seed candidate/control workloads, join isolated-process raw trials by `(input,n,trial,seed)` and report **both** ratio-of-medians and median seed-paired ratio. If they disagree in direction around 1.0, the result is distribution-sensitive and is automatically audit-flagged; do not choose whichever estimator favors the candidate. `benchmarks/compare_seed_aligned.py` enforces seed identity and flags direction conflicts.
- `benchmark.sh` now runs `benchmarks/validate_benchmark_suite.py` before aggregation and records executable/source/runner/validator hashes in suite metadata. A failed validation blocks aggregation.
- **Layout/codegen guardrail (E371 correction):** compiler/layout/codegen differences are diagnostic triggers, not standalone rejection criteria. If a candidate changes unrelated emitted code, expand causal acceptance and recheck suspicious cells under the evidence-integrity rules; retain the candidate when validated performance/correctness/contract evidence shows a material win and no unacceptable regression. Withhold/reject only for measured adverse behavior, not byte-identity loss by itself.
